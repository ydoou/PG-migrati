# migrati

Web-приложение для миграции базы данных PostgreSQL из одного инстанса в другой.
Указываешь два соединения, нажимаешь «Запустить миграцию» — получаешь полный
перенос: схемы, типы, таблицы, данные, sequences, ограничения, индексы и views.

## Возможности

- Поддерживает любые две инсталляции PostgreSQL (≥ 10).
- Переносит:
  - схемы (`CREATE SCHEMA`),
  - расширения (`CREATE EXTENSION`),
  - enum-типы и domain-типы,
  - sequences (с восстановлением `last_value`),
  - таблицы (включая `IDENTITY` / `SERIAL` / `GENERATED`),
  - данные через **бинарный `COPY`** (`pg-copy-streams`),
  - PRIMARY KEY / UNIQUE / CHECK / FOREIGN KEY,
  - индексы,
  - views.
- Real-time лог и прогресс в браузере (Server-Sent Events).
- Опциональная очистка целевых схем (`DROP SCHEMA … CASCADE`).
- Отключение триггеров на время загрузки данных
  (`SET session_replication_role = 'replica'`).
- Не требует установленных утилит `pg_dump` / `psql` — всё через библиотеку `pg`.

## Требования

- Node.js ≥ 18.
- Сетевой доступ к обеим базам PostgreSQL.
- Учётные записи с правами:
  - на source — `SELECT` на все нужные таблицы и `USAGE` на схемы;
  - на target — обычно `CREATE` на БД и владение схемами; для отключения
    триггеров и установки расширений желателен `superuser`.

## Установка

```bash
npm install
```

## Запуск

```bash
npm start
```

По умолчанию приложение слушает `http://localhost:3000`. Порт можно
переопределить переменной окружения `PORT`:

```bash
PORT=4000 npm start
```

## Использование

1. Открой `http://localhost:3000`.
2. Заполни соединения **Source** и **Target** (URL вида
   `postgres://user:pass@host:5432/db` или раздельные поля).
3. Нажми **Проверить соединение** на каждой карточке.
4. Нажми **Анализировать source** — увидишь список схем и таблиц.
   Можно снять галочки со схем, которые не нужно переносить.
5. (Опционально) включи **Очистить целевые схемы**, если в target уже что-то есть.
6. Нажми **Запустить миграцию**.

В разделе прогресса появятся фазы (`schemas → types → tables → data →
constraints → indexes → views`), прогресс-бар по таблицам и подробный лог.

## Архитектура

```
src/
  server.js     Express + SSE endpoints
  migrator.js   Оркестрация миграции
  inspector.js  Чтение метаданных и сборка DDL из source
  public/
    index.html  UI (Tailwind CDN)
    app.js      Frontend-логика
```

API:

| Метод | Путь                                   | Назначение                            |
| ----- | -------------------------------------- | ------------------------------------- |
| POST  | `/api/test-connection`                 | Проверка одного соединения            |
| POST  | `/api/inspect`                         | Список схем и таблиц источника        |
| POST  | `/api/migrate`                         | Старт миграции, возвращает `jobId`    |
| GET   | `/api/migrate/:jobId/events`           | SSE-поток событий (`log/progress/done`) |

## Ограничения

- Не переносятся: функции, процедуры, триггеры, materialized views,
  partitions с собственным DDL, политики RLS, comments, custom collations.
  Если нужно — расширь `inspector.js`.
- Расширения создаются только если у target-роли есть на это права.
- Большие БД — зависит от пропускной способности сети между source и target;
  данные идут через машину, на которой запущен `migrati`.

## Безопасность

- Соединения принимаются из формы и не сохраняются на диск.
- Не запускай этот сервис в открытой сети без авторизации — он позволяет
  читать и писать в любые базы, до которых дотянется по сети.
